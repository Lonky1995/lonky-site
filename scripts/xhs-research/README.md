# 小红书竞品调研工具

为「宝妈 × AI 副业 / 重返职场」赛道做的竞品笔记采集与分析。
回答三个问题：**什么标题结构真的跑得动、同行在踩哪些雷、哪些痛点还没人答。**

## 为什么分两步

`collect`（抓取）和 `analyze`（分析）完全解耦，中间是一个 JSON 文件。

这样做的原因：抓取是脆的（平台改版、风控、登录态过期），分析是稳的。
解耦之后，**抓取挂了也不影响分析**——手工整理一份符合 `Dataset` 结构的
JSON 照样能出报告。数据抓一次，分析可以反复重跑。

## 安装

调研工具的依赖不进主项目的 `package.json`（免得拖慢 Vercel 构建）：

```bash
npm i -D playwright
npx playwright install chromium
```

## 用法

```bash
# 1) 首次登录（开浏览器扫码，登录态存在 ~/.cache/xhs-research/profile）
npm run research:login

# 2) 采集
npm run research:collect -- \
  --keywords "宝妈 AI 副业,全职妈妈 重返职场,AI 接单 兼职" \
  --limit 40 \
  --out data/research/xhs-2026-08-04.json

# 3) 分析
npm run research:analyze -- data/research/xhs-2026-08-04.json
```

产出 `xhs-2026-08-04-report.md`（给人读）和 `-report.json`（给程序读）。

### 参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--keywords` | 三个默认词 | 逗号分隔。**建议一次跑 3–5 个词**，方便横向对比不同切入口的内容生态 |
| `--limit` | 40 | 每个关键词的目标篇数 |
| `--out` | `data/research/xhs-<日期>.json` | 输出路径 |
| `--headless` | 关 | 默认开浏览器窗口，方便发现验证码 |
| `--debug` | 关 | 零命中时导出页面截图和 HTML |
| `--login` | — | 只做登录，不采集 |

## 抓取策略

**抓接口响应，不抓 DOM。** 小红书前端类名混淆且频繁改版，DOM 选择器几周就失效；
搜索页背后的 JSON 接口稳定得多。

具体做法是监听 `page.on("response")`，对返回体做**结构嗅探**——不写死字段路径，
只要一个对象同时具备 24 位 hex 的 id、标题、互动数，就认作笔记。
这样即使接口字段改名（`liked_count` → `likedCount`），也能继续工作。

采集节奏刻意放慢（每次滚动 2.2 秒，切换关键词 6 秒）。被风控拉黑的代价远高于多等几分钟。

## 分析器读什么

- **标题结构**（`patterns.ts` 的 `TITLE_PATTERNS`）——命中率 × 该结构的中位点赞。
  报告里的「相对大盘」列是关键：命中多但跑输大盘的写法，说明已经饱和。
- **收藏比 / 评论比**——区分内容象限。收藏比高 = 干货教程型，吃搜索长尾；
  评论比高 = 情绪共鸣型，吃互动破圈。自己的内容发出后和这两个基准对齐，就知道落在哪。
- **割韭菜话术渗透率**——同行有多少在用这些词。**这张表同时是自己的发布前否决清单。**
- **痛点覆盖度**——覆盖率低但痛点强的，就是空位。

词典都在 `patterns.ts`，是有观点的筛子而非穷举。发现新的高频写法就往里加。

## 已知限制

- **登录态必需。** 小红书未登录基本拿不到搜索结果。
- **接口过滤条件可能需要调。** `collect.ts` 里按 `/api/` + `search|feed|note` 过滤响应。
  若某天零命中，用 `--debug` 导出页面，检查实际请求的 URL 特征。
- **发布时间常缺失。** 列表接口通常不带时间戳，所以「发布时间分布」一节可能样本很少。
  需要精确时间分布的话得逐篇打开详情页，代价高很多。
- **中文高频表述用的是 n-gram 不是分词。** 为一个调研脚本引入分词库不值得，
  2–4 字滑窗加停用词过滤已经够让反复出现的说法浮出来。

## 测试

```bash
npm run test:research
```

分析器是纯函数，测试覆盖统计、模式识别、分位数、Top 榜筛选和边界情况
（零点赞、空数据集）。**抓取部分没有自动化测试**——它依赖真实登录态和线上页面。
